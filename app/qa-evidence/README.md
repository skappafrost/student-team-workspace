# QA Evidence Policy

Screenshots proving UI behavior for PRs that change user-facing surfaces.

## What belongs here

- Screenshots captured while verifying a UI change (before/after, both themes
  when the change touches color or layout).
- Golden-path evidence generated by the e2e suite when a flow changes.

## What does not belong here

- Log dumps, HAR files, videos >1 MB, or anything reproducible in CI.
- Secrets: screenshots must never contain real user data, tokens, or emails
  outside the seeded e2e accounts (`e2e_*@example.com`, `qa_*@example.com`).

## Naming convention

`<unit>-<surface>-<detail>.png`, all lowercase kebab-case:

- `ui-overview-dark.png` — the `ui` unit (dashboard surface sweep)
- `qa-chat-03-after-send.png` — a numbered capture inside a manual QA session
- `f07-deadlines-light.png` — captures tied to a tracked work item

## Regenerating the surface sweep

With the dev frontend (`:3000`) and backend (`:8000`) running:

```bash
bun run qa:evidence
```

This captures every dashboard surface in light and dark mode as
`ui-<surface>-<theme>.png` using a throwaway seeded account. Commit only
the surfaces your change touched.

## Size budget

Keep the folder under ~5 MB total. Prefer PNG at 1440×900 CSS pixels. If a
capture exceeds 500 KB, crop or downscale it. Old captures for merged work
may be pruned by the next PR that touches the same surface.
